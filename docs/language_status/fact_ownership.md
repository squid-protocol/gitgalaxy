# COBOL fact ownership: engine vs det translator (#4273)

GitGalaxy derives COBOL facts twice. The **engine** (the scanner: regex fact channels into the master
DB, read through GalaxyIR) and the **det translator** (`gitgalaxy/tools/cobol_to_java/det`, a
tree-sitter parse) each find the same programs' paragraphs, edges, calls, copybooks, data items,
record layouts, moves and EXEC CICS commands. Where they disagree, one of them is wrong or the fact
is defined differently, and a one-shot translation could build on the wrong one. This page records,
per fact channel, which side **owns** the fact (the one a consumer should trust), with the evidence.

The evidence is regenerated by `tests/tools/fact_crosscheck.py` and gated in CI by the **Fact
Cross-check** workflow (`.github/workflows/fact-crosscheck.yml`) against
`tests/cobol_mainframe/fact_crosscheck_ledger.json`.

## What was compared

- **Universe:** the 7 keyed mainframe corpora (`tests/cobol_mainframe/corpora.json`: CardDemo, CBSA,
  GenApp, zECS, DSF, zopeneditor-sample, IBM DBB mortgage), 128 sources with hand-verified answer
  keys; the 54 programs the det-port equivalence cases translate (each with its case's own copy
  directories; all 54 are also keyed); the 112 keyed copybooks (`layouts`); and estate-crucible at
  its pin (v0.4.0, 40 COBOL programs, a generated key whose planted "horrors" cite IBM).
- **Engine side:** `tests/tools/referees/engine_adapter.py` (the referee panel's, #4377) plus
  `offsets`, `moves` and `copy_resolution`.
- **Translator side:** `tests/tools/referees/translator_adapter.py`. Every value comes from the
  structures the translator builds when it translates (expanded `Line`s, `layout.Item` trees,
  `stmt.Paragraph`s); it re-parses nothing.
- **Shapes:** `tests/tools/referees/facts.py` (the answer key's own score shapes), so each side is
  also scored against the keys.
- **Run:** engine `e3ace8a0d` (origin/main, 2026-10-05), tree-sitter-language-pack 1.20.0 and 1.21.0
  (identical results).

## Who owns each fact

| channel | owner | why (the numbers above) | the other side |
|---|---|---|---|
| PROGRAM-ID | **engine** | the translator has no PROGRAM-ID fact (its caller names the program) | — |
| units, unit extents, PERFORM / GO TO edges | **engine** | 100% precision against the keys; the translator's misses are sources it cannot read as one program (estate-crucible PAYMAIN: nested programs) | check. Known engine gap: the main line has no extent (#4302); the translator and the key have it |
| CALL / LINK / XCTL, call targets | **engine** | 100% / 100% on both sides; only the engine resolves an identifier target through its VALUE | check |
| COPY members and their resolution | **engine** | engine 100 / 100 vs the keys; the translator searches a flat directory list and takes the wrong member when one exists in two libraries (estate-crucible H-0034, H-0052: 98.3 / 97.8), splices a program source as a copybook, and misses two COPY statement forms | consumes the engine's resolution since #4468 (`GalaxyIR.copy_resolution`); refuses collisions, gaps and #4459's unexpanded forms by name. The cross-check's translator side takes it too |
| data items: PIC, USAGE (as written), OCCURS, REDEFINES | **engine** | 100% vs the keys on every attribute; the translator agrees on 99.8–100% (its misses come from the COPY defects above) | check |
| VALUE | **engine** for analysis (as written); **translator** for translation (parsed) | the 18 disagreements are spelling: `0225` vs 225, `ALL` vs `ALL '#'` | both kept |
| record layouts / offsets | **translator** for its own translation; **engine** for analysis, checked by this gate | 96.2% agreement on 16,153 values. Engine wrong on 337: section-level COPY REPLACING (#4457) and a COPY continuation (#4458). Translator wrong on 78, every one from COPY resolution or expansion, none from the layout arithmetic. POINTER width (228) is a platform setting: 4 on z/OS, 8 in the GnuCOBOL storage the proofs run on (`oracle_assumptions.md` C9) | revisit having the translator consume engine layouts once #4457 / #4458 are fixed and POINTER width is a parameter: the engine would then match the translator everywhere on these corpora |
| MOVE pairs | **engine** for lineage; **translator** for meaning | engine 100 / 100 vs the keys; the 54 disagreements are CVDA moves (`DFHVALUE(GET)`: the engine keeps the operand, the translator its number) | both kept |
| EXEC CICS commands | **translator** for command semantics (every option, refusing the unmodelled, #4411); **engine** for the resource census | 100% agreement over the verbs the keys census; the translator also reads the commands nobody censuses (ASKTIME, RETURN, SEND TEXT …) | the engine's resource inventory (files, maps, queues, resolved names) stays engine-owned |

The ownership changes where a fact is consumed, not who computes it: both sides keep deriving
every channel, and the gate keeps them honest against each other.

## The gate

- `python tests/tools/fact_crosscheck.py check` fails on any disagreement the ledger does not list
  (an engine change that moves a fact the translator also reads, a translator change that moves one
  the engine reads, or a new estate shape), and on a ledger entry with no cause.
- The ledger is a **two-way ratchet**: a ledgered disagreement that stops reproducing (a fix) also
  fails `check`, listing the ids. **A PR that fixes a disagreement must lower the ledger in the same
  PR** (`python tests/tools/fact_crosscheck.py update`, then commit the ledger), so the ledger only
  shrinks and a later regression cannot hide behind a stale id. The engine fixes (#4457, #4458) and
  translator fixes (#4459–#4462, #4467) will each do this.
- New disagreements: read the source, fix the side that is wrong, or `update` and
  `assign CAUSE 'REGEX' --side engine|translator|definitional --issue N --summary ...`. Never mark a
  defect definitional to get green.
- Runtime: ~6 s for the comparison once the scans exist; CI scans 7 corpora plus the crucible first.
