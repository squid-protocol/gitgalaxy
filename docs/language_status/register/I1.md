- **What is modelled** (#4893). A batch DL/I program: IMS enters it at ENTRY 'DLITCBL' with the PSB's DB PCBs (CMPAT=NO,
  a DLI region), and it issues `CALL 'CBLTDLI' USING function pcb io-area [ssa ...]`. The COBOL side runs against
  `tests/equivalence/ims/ggdli.c`, the det port against `cobolrt/dli/DetDli.java`: one rule set, one set of refusals.
  The calls are GU, GHU, GN, GHN, GNP, GHNP, ISRT, REPL and DLET (IBM IMS 15.3 Application Programming APIs, "DL/I calls
  for database management"; the application side is in IMS 15.3 Application Programming, ibm.com/docs/en/SSEPH2_15.3.0/pdf/IMS_15.3_Application_Programming.pdf).
- **The database is stated, not connected.** The case names its DBD and PSB sources, which the engine's own macro
  reader parses (`gitgalaxy/core/ims_gen.py`), and a seed: the corpus's own HD unload (I6), or segments the case writes.
  Both sides read the same `dbd.cfg` / `psb.cfg` / `seed.<DBD>`, and each writes the database it ended with. The
  harness compares those segment by segment, every field of the segment's copybook layout (`equivalence_ims.diff_db`).
  The database is a hierarchy in hierarchic sequence: each parent's children by segment type in DBD order, and twins in
  sequence-field order (I2). HIDAM, PHIDAM, HISAM and SHISAM are read alike. The HIDAM index is not a database here:
  it only orders the roots by key, which the hierarchy already does.
- **Status codes** (IMS 15.3 Messages and Codes, Volume 4: IMS Component Codes, "Database calls for DL/I status
  codes", ibm.com/docs/en/ims/15.3.0?topic=codes-database-calls-dli-status):
  - blank: success.
  - GA: an unqualified GN / GNP moved up a level. GK: it returned a segment of another type at the same level.
  - GE: segment not found, or ISRT's parent not found. GB: GN reached the end of the database.
  - GP: GNP with no parentage. II: ISRT of a segment whose key its twins already hold.
  - DJ: REPL / DLET without a get-hold call just before. DA: REPL / DLET whose I/O area changed the sequence field.
  - AC: SSA naming a segment the DBD lacks, or SSAs out of hierarchic order. AJ: invalid SSA (qualification start,
    operator, end). AK: invalid field name. AD: invalid function. AM: function the PCB's PROCOPT does not allow.

  Any other condition is refused (I5).
- **RETURN-CODE after the call.** Each call returns 0: the C model returns 0 (GnuCOBOL stores it in RETURN-CODE), and
  the det port stores 0. IBM is silent on what the DL/I language interface leaves in register 15 for a COBOL
  CALL (the IMS 15.3 Application Programming pages name only the status code in the PCB). A program that reads RETURN-CODE after a DL/I call, or ends without setting it, relies on this assumption:
  PAUDBUNL ends RETURN-CODE 0 after its last GN (GB).
- **IBM trace (#8700, 2026-11-19; IMS 15.4 Application Programming APIs "REPL call", "DLET call", "ISRT call", and
  Messages and Codes Volume 4 "DL/I codes" DA, DJ, II; 15.4, the register cites 15.3).** Rules `RT-DLI-ISRT` and
  `RT-DLI-CHANGE`.
  - **DIFFERS, REPL / DLET after a hold (RT-DLI-CHANGE).** DJ (Volume 4): "The segment was already deleted using this PCB.
    After one Get Hold call, multiple REPL calls or a DLET call following a REPL call are valid, but multiple DLET calls
    are not." DLET (APIs): "IMS rejects the DLET call if the preceding call for the PCB was not a Get Hold, REPL, or
    DLET call", and GHU: "you can issue more than one REPL or DLET call to the segment if you do not issue intervening
    calls to the same PCB". The runtime (and `ggdli.c`) clears the hold on every call, so a second REPL, or a DLET after
    a REPL, answers DJ where IBM succeeds. Not reached: PAUDBUNL issues only GN. The rest of the rule is **MATCHED**:
    DJ with no get-hold before, and DA: "tried to modify the key field in the segment" (Volume 4, DA); DLET "deletes the
    held segment, along with all its physical dependents".
  - **Refused where IBM answers.** REPL with an SSA: "Using a qualified SSA is invalid and results in an AJ status code",
    and "Use only unqualified SSAs on a REPL call"; the runtime refuses any SSA on a REPL or DLET (`"a REPL with SSAs"`)
    rather than answer AJ. A DLET takes one unqualified SSA only after a path get-hold: handled for the D-coded path
    (`changePath`), refused otherwise. REPL of a segment that is not replace-sensitive with changed data is AM in IBM;
    the runtime answers AM by PROCOPT, not by comparing the data.
  - **ISRT, MATCHED.** "If the segment type you are inserting has a unique key field, the place where IMS adds the new
    segment occurrence depends on the value of its key field"; "The last SSA must be unqualified"; "If IMS returns a GE
    status code, at least one of the parents does not exist"; II: "tried to insert a segment that already exists ... A
    segment with an equal physical twin sequence field already exists for the parent." **Still ASSUMED:** the
    FIRST / LAST / HERE insert rules for a non-unique or absent key (IBM: the DBD's RULES parameter; whether the
    runtime reads it was not checked here), and load-mode statuses LB / LC / LD / LE (not in the text read).
- **IBM trace, part 2 (#8700, 2026-11-20; IMS 15.4 Application Programming "Multiple qualification statements" and
  "Data areas in GSAM databases"; Application Programming APIs "Command codes"; Messages and Codes Volume 4 "DL/I status
  code explanations" AC, AD, AJ, AK, AM; 15.4, the register cites 15.3).** Rules `RT-DLI-SSA`, `RT-DLI-CALL`, `RT-DLI-STATE`.
  - **RT-DLI-CALL, MATCHED.** AD (Volume 4): "Either the function parameter on the call is invalid or the function is
    not supported for the type of PCB specified in the call"; its Table 17 lists AD under GU, GN, GNP, DLET, REPL and
    ISRT. AM: "The call function is not compatible with the processing option in the PCB, the segment sensitivity, the
    transaction-code definition, or the program type", with "The minimum processing options for these calls are D for
    DLET, R for REPL, and I for ISRT". The refusal of every other call is a stated boundary (I5), not an IBM result.
    Trap: the text copy's two-column dump puts "Only applies to full-function DEQ calls" inside AD's paragraph; Table 17
    still lists AD for the other calls, which is what the runtime relies on.
  - **RT-DLI-SSA, stays ASSUMED.** MATCHED parts: AC, "The call specifies two SSAs for the same hierarchic level" and
    "the SSA specifying that segment name is not in its correct hierarchic sequence"; AK, "An SSA contains an invalid
    field name"; AJ, "the format of one of the SSAs is invalid"; AND / OR, "Logical AND ... (coded * or &)", "Logical
    OR ... (coded + or |)", "A set is a number of qualification statements that are joined by an AND ... Each OR starts a
    new set", so AND binds tighter; the independent AND is "Use it only with secondary indexes" (refused here, I5). The
    command-code table lists the null code: "Null. Use an SSA in command code format without specifying the command
    code". **Not traced / differs by refusal:** (1) the runtime's limit of 16 qualification statements (`MAX_TERMS`) has no
    IBM source: IBM says "You can use a maximum of 1024 qualification statements on a call" and "up to 15 SSAs" per call.
    A statement count between 17 and 1024 is refused here where IBM answers. (2) The runtime refuses `L` except on the
    last unqualified SSA of a GU, `P` except on a GU, and `C` except as the one SSA of a GU; IBM's Table 57 allows each
    on every get, and `C` also on ISRT ("You can use the C command code for all Get calls and for the ISRT call"). These
    are refusals, not wrong answers, so the rule stays ASSUMED with the choice named, not DIFFERS.
  - **RT-DLI-STATE, stays ASSUMED.** IBM documents the stored order, not how a harness loads it: "When you use a
    sequential access method, the segments in the database are stored in hierarchic sequence, one after another"
    (Application Programming, "Sequential access"); a unique sequence field fixes the twin order (ISRT quote above, and
    I2); for FIRST / LAST / HERE the DBD's insert rule applies only to a segment "with no sequence field or with a
    nonunique sequence field" and "The value is ignored when specified for a segment type with a unique sequence field"
    (Application Programming APIs, DBD AMBIGUOUS INSERT). Not IBM text: refusing an out-of-order seed, and the DBD / PSB
    configuration reader. Those are the harness's, so they stay assumed (I6 for the unload).
