- **IBM.** With MQGMO_WAIT the call waits up to WaitInterval for a suitable message, then fails with
  MQRC_NO_MSG_AVAILABLE (2033).
- **Assumed.** The case's queues are the whole world of the task: nothing else puts while it runs, so a wait that
  finds no message ends the same way it would after the interval, and the models answer 2033 at once (the clock does
  not move). A wait with MQWI_UNLIMITED on an empty queue would never end: refused by name, as is a negative
  WaitInterval other than MQWI_UNLIMITED (IBM: MQRC_WAIT_INTERVAL_ERROR, not modelled).
- **Not modelled.** A concurrent producer, MQGMO_SET_SIGNAL, and triggering itself (CKTI starting the transaction): a
  case states the trigger message the task is started with instead (W8's neighbour: `start_data`, the MQTM).
- **IBM (document).** IBM MQ Application Programming Reference, MQGET and MQGMO (WaitInterval, MQGMO_WAIT,
  MQWI_UNLIMITED), and the MQRC_NO_MSG_AVAILABLE (2033) and MQRC_WAIT_INTERVAL_ERROR reason codes
  (https://www.ibm.com/docs/en/ibm-mq/9.3?topic=reference-mqget-get-message). The wording is paraphrased, not verbatim.
- **Declared difference.** IBM waits the full WaitInterval before 2033; the models answer at once because no
  producer can put meanwhile.
- **IBM trace (#8700, 2026-11-20; IBM MQ 9.4 Developing Applications Reference, MQGMO "WaitInterval"; the register cites 9.3).**
  Rule `RT-MQ-GET`.
  - **Matched:** WaitInterval is "the approximate time ... that the MQGET call waits for a suitable message to arrive ...
    If no suitable message has arrived after this time has elapsed, the call completes with MQCC_FAILED and reason code
    MQRC_NO_MSG_AVAILABLE", and "There is no wait, or delay, if a suitable message is available immediately". MQWI_UNLIMITED
    is "Unlimited wait interval"; WaitInterval "must be greater than or equal to zero, or" that value (a negative one
    is MQRC_WAIT_INTERVAL_ERROR, listed in the MQGET reasons).
  - **Still ASSUMED:** IBM says the wait "on z/OS ... is affected by system loading and work-scheduling considerations";
    the result 2033 after no producer puts is IBM's, but "no producer" is the case's assumption, and IBM is silent on it.
    The time not passing is the declared difference above.
  - **MQGMO_CONVERT:** "converts the application data in the message to conform to the CodedCharSetId and Encoding values
    specified in the MsgDesc"; "If conversion is successful, the CodedCharSetId and Encoding fields ... are unchanged".
    A message already in the asked form needs none (matched); any real conversion stays refused.
