- **Compared.** Each SEND MAP's symbolic map: the data, the attribute, colour and highlight subfields, and the cursor
  (length -1).
- **Not modelled.** What a 3270 shows after BMS merges the physical map, MAPONLY, DATAONLY, ERASE and FRSET. Two
  ports with equal symbolic maps could differ on a terminal only if BMS itself differed.
- **IBM.** CICS TS Application Programming Reference, EXEC CICS SEND MAP (https://www.ibm.com/docs/en/cics-ts/6.x?topic=summary-send-map):
  SEND MAP merges the application data structure (the symbolic map) with the physical map BMS holds, and builds the
  3270 data stream; MAPONLY sends the map with no data, DATAONLY only the data, ERASE clears the screen first, and
  FRSET resets the modified-data tags. The wording is paraphrased, not verbatim.
- **Declared difference.** IBM's result is the 3270 data stream BMS builds; the oracle and the port are compared one
  step earlier, at the symbolic map, since BMS itself is not modelled.
- **IBM trace (#8700, 2026-11-20; CICS TS 6 Application Programming, "Developing CICS Applications", SEND MAP, local manual text).**
  IBM: "A value is present. ... For field attributes bytes, the value must not be null ( X'00' ) or one of the values that remain
  from an input operation ( X'80' , X'02' , or X'82'). For extended attribute bytes, the value must not be null. ... For display
  data, the first character of the data must not be null."
  - **MATCHED:** a null (X'00') attribute, extended attribute or leading data byte is absent.
  - **DIFFERS (declared here, `RT-CICS-BMS-SUBFIELDS`):** `DetCics.subfields` also drops a space, which IBM sends (a field attribute
    of X'40' is present), and sets X'80' / X'02' / X'82', which IBM treats as absent. The receiving side's `<f>L` is the text without
    trailing blanks; IBM does not say it counts the blanks keyed, so that half stays with X54's blank-field note.
  - **Landed (#7955, PR #8827):** both sides now record a space (X'40') and a NUL (X'00') as values. This kills HXATTR `722da01d4e`
    and HXEXT `2f61febdd4`. The earlier "tried, not landed" premise was wrong: on an uncleared map (`ca-bytes-entry-clear`)
    GnuCOBOL holds spaces, not nothing, so the port and the oracle agree and no write tracking in the runtime is needed.
    A subfield never given, a written X'00' and a written X'40' are three different states on the compare
    (`test_7955_a_byte_never_given_is_not_a_written_nul_or_space`). HXEXT `8ec71a9459` (a repeat of the `MOVE LOW-VALUES TO HXM2I`
    just before it) survives seven oracle inputs and carries no stated verdict until a seed samples it.
