- **What IBM says.** z/Architecture Principles of Operation (SA22-7832) defines every instruction the subset uses (MVC overlap left to right, CLC, LA, STH, ST, L, TR, BC masks) and the condition code. The CICS command semantics are those of the existing X entries (X32 WRITE OPERATOR, X70 ABEND); DEFINE DCOUNTER: a duplicate name is INVREQ RESP2 202, a bad name INVREQ RESP2 404 (CICS TS 6.x, DEFINE DCOUNTER).
- **Modelled.** The interpreter runs the assembler text (EBCDIC storage, 32-bit registers, a real condition code, EXEC CICS as recorded events). `test_zecsnc_interpreted_events_equal_the_oracle_run_of_the_lowering` pins, per scenario, the oracle's event sequence and payload text (TD record, operator message, START FROM, SEND, ABEND code, RETURN) and the named counters created, taken from a GnuCOBOL run of the lowering. A second test pins the `WRITE OPERATOR` ROUTECODES (X'0111') and NUMROUTES (2) the source declares, which the stub does not record (it logs only the text length).
- **What we assume (ASSUMED).** (1) The interpreter is hand-written and could share a misreading of the POPS with the lowering; independence is of code, not of author. (2) Payloads are compared as text: the lowering stores `=C'..'` and text as ASCII, z/OS as EBCDIC (design-doc assumption 3). (3) DFHEISTG is uninitialised on z/OS; the comparison relies on the oracle's space fill, which the interpreter is told (`facts["fill"]`). (4) The end COMMAREA of ZECSNC is not compared (non-linked).
- **Found by the cross-check.** Slice 4's FORMATTIME wrote into a copy of storage, and the SS length parser ignored `D(L)` (`MVC Z_EXP+2(2),Z_TRAN+2` copied 4 bytes, so START carried `_Z01`). Both were interpreter bugs, fixed in the same slice; the lowering agreed with the oracle throughout.
- **Status:** ASSUMED. The oracle is GnuCOBOL plus our stub, not z/OS. Slice 6 added a per-instruction differential of the interpreter against the lowered COBOL under `cobc` (`tests/tools/hlasm_diff.py`: LA, SLL, SLDL, SR, BCT, STH, CH; 71 boundary snippets, registers agree, 0 differences). Left: the storage-byte instructions (MVC, TR, STCM, IC, CLC, OC, XC) in that differential, and a general assembler path.
