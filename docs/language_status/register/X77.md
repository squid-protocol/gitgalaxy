- **What IBM says** (Enterprise COBOL for z/OS 6.3 Language Reference, JSON PARSE: https://www.ibm.com/docs/SS6SG3_6.3.0/lr/ref/rlpsjsop.html and its sub-pages). The members of the JSON object are matched by name to the subordinate items of the receiving group; a JSON name with no data item is ignored and an item with no JSON member is left unchanged; NAME OF renames an item, SUPPRESS leaves one out; a string goes to an alphanumeric item (left-justified, padded with spaces) and a number to a numeric item (aligned on the decimal point); WITH DETAIL only widens what the exception condition reports. A text that is not valid JSON, or a value that does not fit or has the wrong type, raises the exception condition (JSON-CODE nonzero, ON EXCEPTION).
- **Modelled.** `det/stmt.py` `_json_parse` parses the statement, `det/gen.py` `json_parse` builds the receiving tree (shared with JSON GENERATE through `json_tree`) and refuses the shapes below by name, `cobolrt/JsonParse.java` reads and stores. A statement it cannot take keeps the `JSON PARSE (...): not modelled` hole text, with the reason for the shape appended.
- **What we assume.** (1) The text is one JSON object whose members map to the group's subordinates; the group's own name is not in the text (unlike the GENERATE wrapper). (2) Names match case-sensitively and exactly. (3) The exception condition (#7524): with ON EXCEPTION / NOT ON EXCEPTION, malformed text, text that is not a JSON object, a value of the wrong type, empty text, text after the closing brace and no name matching raise it (ON EXCEPTION runs, else NOT ON EXCEPTION); without the phrases each is a runtime `Hole`. Malformed text and text after the closing brace store nothing; after a type or size failure the items matched before it keep the values stored (assumed: IBM's text is read as leaving the receiver unspecified, the model stores left to right). A string longer than its item and a number too large for it are nonexception in IBM (JSON-STATUS 256 / 128, stored anyway, in a form the text does not state), so they are a `Hole`; so are a JSON array, `true`, `false`, `null`, a non-object top level (no JSON-CODE stated), and JSON-STATUS after an exception. A number with more decimals than the item, a negative number for an unsigned item, an exponent, a repeated name in one object and any character beyond ASCII are a `Hole` even with the phrases, never a guess. JSON-CODE (S9(9) BINARY) is the exception code of the Programming Guide's Table 109 and 0 on success; JSON-STATUS (#7709): a program that names it and has a JSON PARSE gets a hidden item of IBM's declared shape, `PICTURE S9(9) USAGE BINARY VALUE 0` (a JSON GENERATE alone does not: IBM does not say it sets the register, so the name stays unresolved and the port is refused). After a parse with no exception it holds the runtime's bits 1 (a data item had no pair) and 2 (a pair matched no item) of Table 108, 0 when neither happened. Assumed: the register is reset at each JSON PARSE (IBM: it holds the conditions "at termination of a JSON PARSE statement"; the reset rule is not stated). After an exception its value (the bits seen before it) is a runtime `Hole`, never a guess. A program's own JSON-STATUS item is kept. A program's own JSON-CODE item is kept. The hidden JSON-CODE register is S9(9) BINARY, IBM's declared shape (#7709). (4) WITH DETAIL changes nothing the model reports, since only the exception condition uses it.
- **Packed and binary numbers (#7524, #7709).** A COMP / COMP-3 / COMP-5 numeric receiver takes the number by the same rules as a DISPLAY one (decimal alignment, no extra decimals, no negative for an unsigned item, a value past the PICTURE digits is the exception condition); the store is the runtime's `Cobol.store`, IBM's text states no other byte layout. A fixed OCCURS table receiver is taken (next bullet); an OCCURS DEPENDING ON receiver stays refused for PARSE.
- **Fixed tables (#7524).** A fixed `OCCURS` item (elementary or group elements, nested fixed tables too) in the receiving group is a JSON array under the item's name (IBM's table format, the one JSON GENERATE writes): element k of the array goes to occurrence k, by the scalar rules above (a group element is an object matched by name). A value that is not an array is a type mismatch (JSON-CODE 104). Assumed-not-guessed: an array with more or fewer elements than the OCCURS count is a runtime `Hole` (IBM's pages do not state it); a top-level array stays a `Hole`; `null`, `true` and `false` elements stay a `Hole`. Items stored before a failing element keep their values (as above). A table as the receiving item itself is refused.
- **Status:** ASSUMED, **oracle-unbacked**; a port using it is reported as assumed (IBM-documented). JSON-STATUS bits 4-512 (duplicate names, null, which the model refuses or does not reach), JSON-STATUS after an exception, CONVERTING, ODO tables and float items are later slices of #7524 (SUPPRESS WHEN / EVERY is a JSON GENERATE phrase in IBM's syntax, not a PARSE gap).
