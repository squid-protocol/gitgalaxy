# One program, two independent translations: GenApp LGACDB01, scanned and proven

*A post-hoc comparison. Status: draft, 2026-10-02. Section 4.3 (IBM's Java run through our harness) is in progress.*

## Abstract

GenApp's LGACDB01 (the add-customer program in IBM's CICS General Insurance sample) has been translated to Java twice, independently:
- **by IBM's watsonx Code Assistant for Z (WCA4Z)**, as published with IBM Research's validation papers (Kumar et al., ASE 2024; Hans et al., 2025);
- **by GitGalaxy's deterministic translator ("det port")**, as part of this project.

We compare four files: the original COBOL, the COBOL that IBM's refactoring step produced, IBM's Java, and our det port. We use three lenses:
1. IBM's published validation results;
2. our end-to-end equivalence harness;
3. GitGalaxy's static scanner.

The two translations make opposite trade-offs:
- **IBM's Java** is compact and readable. It covers one of the program's five paragraphs, and leaves the date of birth and the error path in commented-out lines.
- **Our det port** covers the whole program and the two programs it LINKs to, and is proven against real Db2 on four scenarios. But it is about 7× the COBOL's code lines, and its scenarios reach only 6 of 14 branches.

The comparison also exposed two GitGalaxy scanner defects (#4170, #4171).

## 1. Provenance and independence

This is a post-hoc comparison, not a designed experiment.
- **No reference to IBM's work.** GitGalaxy's translator, its equivalence harness and the GenApp cases were built without reference to IBM's papers, code or tests. We did not assess IBM's method or tests while building ours.
  - The first GenApp det ports were proven on 2026-10-01 (commit 3504f767f).
  - LGACDB01 was proven on 2026-10-02 (commit 7def28a8a). Its proof needed CICS named counters, which were added for it.
- **How the comparison came about.** Only afterwards, the same day, did we search for published results on the same programs. We found that IBM's validation papers report on LGACDB01 and other GenApp programs, and that IBM published its LGACDB01 Java.
- **What is shared.** The two efforts share only the input program, GenApp, which is public at github.com/cicsdev/cics-genapp.

This document asks one question: *we translated the same program, so how does our result compare with a published one?*

## 3. Methods

### 3.1 IBM's published validation (as reported; not reproduced here)
IBM's method validates a single paragraph:
- **COBOL tests.** Tests are generated by symbolic execution and run on a real z/OS system, with resource access (SQL, CICS) handled by debugger scripts.
- **Java tests.** The recorded inputs and outputs become JUnit tests. Resource calls are mocked in order, and their arguments are asserted.

For LGACDB01, they selected the INSERT-CUSTOMER paragraph and reported (Kumar et al. 2024, Table 1):
- 100% of paths and branches covered, with 4 paths;
- 11 program outputs and 6 resource outputs;
- 22 assertions (3 on program variables, 19 on resource arguments);
- 4/4 JUnit tests passing.

Across 33 GenApp and IMS Bank programs (105 paragraphs), 84% of the multi-path paragraphs reached full branch coverage (Hans et al. 2025).

### 3.2 Our equivalence harness
Our method validates a whole program in its task:
- **Reference.** The reference behaviour is GnuCOBOL 3 (IBM dialect, EBCDIC signs, TRUNC(STD)) running the original program under our CICS model. SQL goes through our precompiler stub to IBM Db2 Community Edition.
- **The Java side.** The Java port runs the same scenarios against the same Db2 schema.
- **What is compared, byte for byte.** CICS events, the returned COMMAREA, written datasets and every compared table.
- **Case contents.** The LGACDB01 case runs LGACVS01 and LGACDB02 in the same task, and includes named counters. Its four scenarios are hand-written: `add-with-counter`, `add-without-counter`, `add-blank-optional-fields`, `add-long-email`.
- **Limits.** Where our reference may differ from z/OS is listed in `docs/language_status/oracle_assumptions.md`.

### 3.3 GitGalaxy static scan
Each file was scanned on its own with `galaxyscope` at main 582caf5f7, with default settings. The det port is admitted by its provenance header (#4164). We report `file_data` and `function_data` readings.

IBM's papers describe validating one paragraph per program, and this repository reflects that scope. The comparison below is therefore uneven by design: a paragraph translation against a program translation. We note where that matters.

### 4.2 Validation results

| | IBM (reported) | Ours |
|---|---|---|
| Unit | INSERT-CUSTOMER paragraph | Whole task: LGACDB01, LGACVS01, LGACDB02 |
| Reference | z/OS (real) | GnuCOBOL, CICS model, real Db2 LUW |
| Resources on the Java side | Mocked (in-order call stubs) | Real Db2 tables, named counters, VSAM model |
| Tests / scenarios | 4 generated (one per path) | 4 hand-written |
| Coverage | 100% of the paragraph's paths and branches | 3/4 paragraphs, 6/14 branches of the program |
| Outcome | 4/4 pass | Proven: every scenario's events, COMMAREA, datasets and tables equal |

IBM's coverage is complete for the unit it chose. Ours is lower but spans the whole program: the INSERT failure path (`MOVE '90' TO CA-RETURN-CODE`, `PERFORM WRITE-ERROR-MESSAGE`) is never reached, because our harness doesn't inject SQL failures (#4173). IBM's symbolic test generation is the stronger approach to coverage (#4175).

### 4.6 Static reading of IBM's `insertCustomer`
Eleven lines of IBM's `Lgacdb01.java` are commented-out code. They include, in both INSERT branches:
```java
// ps.setDate(4, caCustomerRequest.getGenasa1Customer().getDateofbirth());
```
and, in both exception handlers:
```java
// caReturnCode = 90;
// errorMsg.writeErrorMessage();
```
In their place is `System.out.println("[EXCEPTION CAUGHT] " + exception);`. The connection is the placeholder `DriverManager.getConnection("endpoint_url")`.

Reading the code alone, we expect the following against a real database: the unset DATEOFBIRTH parameter makes the INSERT fail; the failure is printed and swallowed; and the caller sees no error return. Section 4.3 tests this expectation; it is not yet a result.

GitGalaxy's tech-debt risk reads 84 for this file, against 10 for the det port. But its commented-out-code signal reads 0, because the Java rule only recognises commented lines that begin with a keyword (#4171).

## 5. What each lens can and cannot see

| Lens | Sees | Misses |
|---|---|---|
| IBM validation (as published) | Every path of the chosen paragraph. The arguments passed to each resource call. A real z/OS reference. | Other paragraphs. Behaviour that depends on a real resource, such as how the database treats an unset parameter, because resources are mocked. |
| Our harness | The whole task against real Db2 and a CICS model, compared byte for byte. | Branches no scenario reaches, such as SQL error paths (#4173). Reference differences listed in the oracle register (GnuCOBOL, not z/OS). |
| GitGalaxy scan | Scope (functions, IPC dropping to 0), debt pressure, output by print, size and token cost, all without running anything. | Behaviour. Equivalence. Commented-out statements in Java (#4171). Its Java complexity is unreliable around SQL strings and ternaries until #4170 is fixed. |

The lenses complement each other. The scan flagged IBM's file (IPC 14 → 0, tech-debt 84, print-based error handling) in seconds, without running it. The harness decides whether the behaviour is equal. IBM's path-complete test generation covers the branches our hand-written scenarios miss.

## 6. Threats to validity
- **One program, and an uneven comparison.** This is a single program, and IBM's published Java is a single paragraph. We do not generalise to WCA4Z's quality.
- **IBM's code is old.** It dates from 2024 (COBOL slice 2024-06-11, repository 2024-10-11) and may not reflect the current product.
- **IBM's reported validation passes on its own terms.** Any divergence we find concerns behaviour outside its mocked scope; it does not show their tests were wrong for what they assert.
- **Our reference is not z/OS.** See `oracle_assumptions.md`.
- **Our coverage is modest.** 6/14 branches.
- **Scanner readings carry the bugs in #4170 and #4171.** They will be re-measured after those fixes.
